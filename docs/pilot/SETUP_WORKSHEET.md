# Stammdaten für den Pilot — manuell ausfüllen

Kein Importskript und keine Produktivkonfiguration. Der Owner benennt reale Werte;
berechtigte Personen legen sie in der bestehenden Verwaltung an. Keine Kontaktdaten,
Ausweisdaten, Tokens oder Zugangsdaten in dieses Repository eintragen.

Zielinstanz: **offen** · freigegebener Build: **offen** · Zuständigkeit: **offen**

| Einrichtung | Ownerwert / Entscheidung | Kontrolle vor Freigabe |
| --- | --- | --- |
| Kategorien | Offen | Reale frei gewählte Hierarchie, getrennt von Arten und internen Standorten |
| Standorte | Offen | Interner Standortbaum; öffentliche Ortsangabe gesondert freigeben |
| Arten und Ressourcen | Offen | Raum/Maschine/Vermietgegenstand anhand tatsächlicher Nutzung, nicht jeder Raum als Ausleihe |
| Inventar | Offen | Vorhandene Codes/Seriennummern geschützt pflegen; Inventar-only bleibt möglich |
| Einheiten/Pools | Offen | Physische Einheiten bewusst mit Asset verbinden; reine Räume logisch; nur gleichwertige Einheiten poolen |
| Komponenten | Offen / im Pilot nicht verwendet | Erforderliche Komponenten und eigene Voraussetzungen/Rechte mitprüfen |
| Öffentliche Inhalte | Offen | Titel, Beschreibung, Bilder, veröffentlichter Ortsfilter; keine Seriennummern/Lagerpfade/Personen |
| Gruppen | Offen | Echte Aufgaben, explizite Aktionen und Scopes; Mitarbeitendenmarker gewährt nichts |
| Buchungsgrenzen | Offen | Je Gruppe/Ressource gültige Horizonte, Dauer, Granularität und Storno; keine erfundenen Standardzusagen |
| Zeitpläne | Offen | Öffnung, Abholung/Rückgabe und Ressourcennutzung getrennt; harte Schließungen/Übergangszeiten prüfen |
| Außerhalb der Öffnung | Offen / nicht freigegeben | Nur ausdrücklich passende Gruppen, Ressourcennutzung und harte Schließungen weiterhin beachten |
| Vereinbarungen | Ownertexte offen | Allgemeine Ausleihe/Haftpflicht und mehrere ressourcen-/assetbezogene Zusätze; publizierte Versionen und Eigenbestätigung |
| Einweisungen | Offen / nicht erforderlich | Nur tatsächlich erteilte Nachweise; keine automatische Erteilung, Ablauf oder Einzelentziehung |
| Konten | Registrierte verifizierte Konten, konkrete Anlage offen | Vor physischer Buchung vollständiges Profil; erste Ausgabe mit Ausweisprüfung ohne Dokumentnummer/-kopie |
| Einladungen/Mail | Freigegebene Empfänger/Absender offen | Keine realen Einladungen ohne abgestimmten Test; Reviewmail bleibt lokal |
| Authentik | Betreiberprüfung offen | Komfortlogin für Mitarbeitende, lokaler Login unabhängig, keine Gruppen-/Adminclaimübernahme |
| Scanner/Etiketten | Gerät und Bedienplatz offen | HID/Enter, manuelle Eingabe, schnelle Folgen, Fokus und Datenschutzreset am echten Gerät |

Reihenfolge: Kategorien/Standorte/Arten → Inventar → Ressourcen/Einheiten →
Gruppen und Zeitregeln → Texte/Voraussetzungen → Rollenprobe → bewusste
Veröffentlichung ausgewählter Angebote. Dazwischen mit normalen und eingeschränkten
Konten kontrollieren; Adminrechte ersetzen keine operativen Grants.

Eingegebene Daten bleiben reguläre Geschäftsdaten. Es gibt keinen automatischen
Pilotreset. Vor Änderungen, die frühere Zusagen betreffen, Auswirkungen prüfen und
vorhandene Nachweise erhalten. Ausfüllbare [Ergebnisaufgaben](TASKS.md).
