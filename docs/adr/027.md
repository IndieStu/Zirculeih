# ADR-027 — Production-readiness boundaries and recovery evidence

19.10.2026, [Phase-12 authorization](../OWNER_APPROVAL_PHASE_12.md).

Preserve the modular monolith and all accepted domain/authorization distinctions.
Production readiness adds operator tools and explicit preflight checks, not a new
runtime service or deployment authorization. Default development behavior remains
available. Production checks do not configure TLS, roles, privacy or SMTP silently.
A separately enabled restore mode disables OIDC/outgoing mail; a restored outbox
must not be consumed or marked sent as a side effect of verification.

Backups combine a native PostgreSQL custom dump and a stopped-write media snapshot.
Use the already reviewed cryptography AES-256-GCM primitive with a fresh 96-bit
nonce, versioned authenticated envelope and streaming IO. The randomly generated
32-byte encryption key is a separately protected operator file; signing/provider
secrets are separately protected recovery material, never public review artifacts.
No password-derived key or invented cipher. Authentication completes before any
archive extraction. Strict manifest/path/type/size/hash checks, no symlinks, and an
empty destination prevent accidental traversal/overwrite. The bundler does not run
SQL or stop services: the operator explicitly quiesces writers and restores only to
a new empty DB with matching PostgreSQL tooling. No destructive automatic rollback.

The drill uses fictional data in UUID-prefixed disposable source/target databases,
never existing review/production DBs. Native dump/restore, media byte hashes,
complete table-data fingerprints, retained domain constraints and no-mail behavior
are verified. Backup key loss or signing-key loss cannot be repaired by this tool.
Real backup storage, off-host copies, access control, retention and operator RPO/RTO
still require explicit owner decisions before production; timings are measurements,
not a recovery guarantee. No automatic history anonymization/deletion policy.

Security/SBOM evidence records exact locks, component licenses/hashes, audit source
and time. Unknown/unavailable results are not clean scans; findings and release
blocks stay visible. Accessibility automation and keyboard/responsive observations
are evidence, not blanket WCAG certification. German remains the supported locale;
English UI release requires a complete reviewed catalog, not a partial language switch.
Staging/owner signoff and Phase 13 remain human gates.

The baseline Bookworm runtime scan found HIGH/CRITICAL OS advisories. Refresh the
official digest-pinned images to Debian 13 while retaining Python 3.12/PostgreSQL
17; scan both application and database images, retaining the baseline and current
findings without silent suppression. This is an engineering image change only.
Existing database volumes are not automatically migrated: libc/collation changes
require a planned logical restore into a new volume, index/collation verification,
and retained rollback material under operator authorization.
