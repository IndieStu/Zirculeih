# ADR-022 — Phase-7 qualifications, selected capacity and atomic bundles

2026-10-17. Implementation decision under explicit Phase-7 authorization; existing
policy, integrity, qualification and domain decisions remain binding.

## Qualifications

Existing global qualification types remain global. New types may belong to one
resource or category; inherited category scope follows the existing scope algebra.
Issuing evidence requires qualification.issue on the type's entire scope, not merely
one resource that uses a broad qualification. Current descendant categories and
applicable resources must also be covered; explicit narrower denials and missing
inheritance cannot be bypassed by issuing a broader certificate. Global types
likewise require current organization-wide coverage. Existing immutable evidence
is not retroactively revoked when issuer permissions later change. Type creation/configuration uses
booking.configure on that scope. Resource/category requirements are additive.
Evidence remains immutable, non-expiring and individually non-revocable. No user
self-certification. Changing requirements never rewrites past evidence.

## Capacity and bundles

ResourceUnit remains the concrete exclusive capacity identity; named unit/pool
selection filters the existing allocator. Public selection labels require
resource.publish when edited on an already published offering. No editable independent capacity counter.
Inactive pools and ineligible assets cannot be selected. Automatic resource allocation
continues to work with the same eligible units.

Bundles refer to other independent bookable Resources, never collapse them into
Asset accessories or treat onsite resources as physical loans. A bounded acyclic
component configuration expands to first-class component Bookings with their own
claims, policies, qualifications, agreements and explicit component selection.
A persistent reservation group records the root and exact members. All required
components commit or roll back together using the existing authorization transaction,
unit locks and SQL constraints. Optional components require explicit selection.
Ordinary isolated component booking remains possible when not otherwise occupied.
Reads/cancellation/checkout must respect the whole group's invariants; no silent
partial reservation or unexpected partial required-component issue. Historical
membership and allocation evidence is immutable. No Phase-8 series or Phase-10
work-order engine is introduced.

## Migration and validation

Additive nullable scopes preserve all existing global qualification types/evidence.
New bundle/configuration/group tables do not rewrite existing Booking/Claim/Loan.
Forward migration and application rollback retain data; no destructive reset.
Security, idempotence, complete rollback, concurrent component competition,
maintenance interference and existing full regression are acceptance gates.
